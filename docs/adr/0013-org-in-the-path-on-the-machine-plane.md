# The organisation travels in the path on the machine plane

## Status

accepted

## Context

ADR 0011 and ADR 0012 settled tenancy for everything Django serves: the Host
names the organisation, `OrganisationMiddleware` resolves it once, and every
admin and public-API lookup narrows through `organisations/access.py`. Both ADRs
recorded the same outstanding exception, and it is not a small one.

Two services on this instance are not Django and never see a usable Host:

- **Titiler** (`titiler-app/`) renders raster tiles straight from MinIO. The
  browser reaches it through nginx on whatever hostname the portal runs on, but
  Titiler itself resolves nothing — it concatenates path segments into an object
  key. Its palette cache is a set of Redis keys Django writes, addressed by
  `catalog:collection:variable`. Its fallback on a cache miss is an HTTP call
  back to Django on the internal container name `georiva:8000`.
- **Martin** serves the zonal-statistics choropleth from a PostgreSQL function,
  `georiva_boundary_stats`, taking `variable`, `time` and `admin_level` as query
  parameters. No Django, no Host, no middleware.

Since #267 a catalog slug is unique only within an organisation, so all three of
those addresses were ambiguous:

- **The COG key.** Storage is org-first (`{org}/{catalog}/…`), but Titiler built
  keys from `{catalog}/…`. Every tile request pointed at a path that no longer
  exists.
- **The palette key.** Two institutions each running a `forecast` catalog shared
  one Redis entry, and whichever Django warmed last decided how both rendered.
- **The Martin query.** A bare variable slug matched across catalogs *and* across
  organisations, so one institution's statistics could be drawn under another's
  palette. This half predates tenancy: the cross-catalog ambiguity was already a
  bug.

The `tile-config` fallback endpoint had a second, blunter problem: the middleware
404s unknown hosts, and `georiva:8000` is one, so in any multi-tenant deployment
every fallback call already failed.

## Decision

**On the machine plane the organisation travels in the address, and Django is the
only thing that ever chooses it.**

Concretely:

- Titiler's routes open with an org segment —
  `/titiler/{org}/{catalog}/{collection}/{variable}/…`. The segment is
  concatenated into the COG key and into the palette key
  (`georiva:palette:{org}:{catalog}:{collection}:{variable}`) and forwarded to
  the tile-config fallback. Titiler interprets none of it.
- `georiva_boundary_stats` requires `org`, `catalog` and `collection` alongside
  `variable`, and joins `variable → collection → catalog → organisation`. A
  triple naming nothing yields an empty tile, not an error.
- `/api/tile-config/{org}/…` takes its organisation from its own first path
  segment. `OrganisationMiddleware` allows this by letting that one prefix
  through *when no organisation answers the host*, rather than 404ing it — and
  no further than that. `/api/` is publicly proxied, so an unconditional path
  exemption would have let any anonymous caller on any tenant's host read
  another organisation's rendering config and learn from the 200 which catalogs
  it runs. On a host that does resolve, the Host wins and the segment may only
  agree with it.
- Every one of these URLs is generated by `core/machine_plane.py`, from a row
  Django already fetched under a host-scoped query.

This is deliberately the option ADR 0012 rejected for the public API. The
argument there was that a path segment gives a request two sources of truth for
the organisation, which can disagree. That argument holds exactly where there
*is* a second source; here there is none. A path segment is not a redundant
copy of the Host on this plane — it is the only copy.

The two planes stay consistent in practice because the same request produces
both: Django writes the tile URL while serving a page it resolved from the Host,
so host and path agree by construction rather than by check.

## Consequences

- Titiler and Martin hold no tenancy logic at all, and gain none as tenancy
  grows. They read the org they were handed. That is the property worth
  protecting: logic copied into a second and third service is logic that drifts.
- A client can still edit the org segment by hand on the two services that have
  no Host to check it against. On this plane that buys nothing it did not
  already have — every asset Titiler serves is a public collection's, and #273's
  private tier addresses the machine plane through the nginx `auth_request`
  gateway (#274), not through path guessing. Martin's function reads only what
  the triple names. The Django endpoint is the one that *does* have a Host to
  check against on public calls, and does.
- Existing palette keys are in the old format and can never be read again.
  `warm_all` now sweeps every `georiva:palette:*` key it did not just write, so
  the format change clears itself on the next startup — and so do the keys of
  renamed, deactivated and deleted variables, which previously outlived them
  indefinitely.
- `create_martin_function` runs from `docker-entrypoint.sh`, so the redefinition
  lands on deploy without an operator step; Martin needs a reload to pick up the
  new function comment. The SQL signature is unchanged but the required
  parameters are not, so a client still sending the old query string gets a loud
  error rather than a wrong tile.
- The browser's direct MinIO reads for encoded PNGs were org-less for the same
  reason and are fixed alongside; the map's asset URLs are org-first now too.
